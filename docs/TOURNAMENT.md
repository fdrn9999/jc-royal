# 6인 SNG 토너먼트 규칙

> 무료·무보상 싱글 테이블 토너먼트(Sit & Go, 최대 6명)의 상태·진행·장애 처리 규칙이다. 구현(`packages/types/src/tournament.ts`, `apps/game-worker/src/tournament.ts`·`room.ts`, `apps/api/src/routes/tournaments.ts`·`admin-tournaments.ts`)은 이 문서를 따른다. 이 문서가 구현보다 앞서 정해졌고, 바꿀 때는 이 문서부터 고친다.

## 범위

| 포함 | 제외(이번 버전) |
|---|---|
| 한 테이블 2–6명, 같은 시작 스택, 시간으로 오르는 블라인드 | 멀티 테이블 토너먼트, 테이블 합치기 |
| 등록·등록 취소·시작·진행·탈락·종료, 순위와 결과 화면 | 리바이·애드온, 늦은 등록 |
| 관리자의 템플릿·개별 대회·진행 제어(마감·시작·취소·일시정지·재개·운영 중단·복구) | 참가비·상금·환급, 칩 보상 |
| 대회 전용 시간 은행(템플릿에서 정함) | 봇 참가, 앤티 |
| | 대회 핸드의 핸드 기록·리플레이·플레이어 통계 |

토너먼트 칩은 그 대회 안에서만 쓰는 숫자다. 지갑·칩 원장(`chip_ledger`)·테이블 세션(`table_sessions`)과 이어지지 않는다. 대회 테이블에서는 바이인·충전·자동 리바이·캐시아웃이 일어나지 않으며, 룸은 대회 좌석에 대해 원장을 부르는 경로를 막는다(`cashOutSeat`가 대회 좌석이면 아무것도 하지 않음).

## 대회 상태

```
registering ⇄ closed ──start──▶ running ──1명 남음──▶ finished
     │           │                  │
     └──cancel───┴──▶ cancelled     └──abort──▶ aborted
```

| 상태 | 뜻 | 들어오는 길 |
|---|---|---|
| `registering` | 등록을 받는다 | 대회 생성, 마감 해제 |
| `closed` | 등록 마감. 새 등록은 없고 등록 취소는 된다 | 관리자 마감 |
| `running` | 진행 중. 테이블이 열려 있다 | 시작(관리자 또는 정원이 차서 자동) |
| `finished` | 한 명이 남아 정상 종료 | 룸의 마지막 핸드 정산 |
| `cancelled` | 시작 전 취소 | 관리자 취소(`registering`·`closed`에서만) |
| `aborted` | 진행 중 운영 중단 | 관리자 운영 중단(`running`에서만) |

- `finished`는 룸이 마지막 생존자를 확인했을 때만 기록된다. 운영 중단은 `aborted`이며 우승자가 없고 정상 종료로 기록되지 않는다.
- 상태 전환은 모두 "현재 상태가 X일 때만"이라는 조건부 UPDATE 한 문장이다. 같은 전환을 두 번 요청하면 두 번째는 0행 변경이 되어 409로 거절된다.
- `version`은 관리자가 보는 상태(대회 상태·일시정지 요청)가 바뀔 때마다 1 오른다. 관리자 조치는 보던 `baseVersion`을 보내고, 다르면 409 `tournament_conflict`와 현재 대회를 돌려준다. 룸의 진행 기록(레벨·핸드 수·생존 인원)은 `version`을 올리지 않아 관리자 조치와 부딪히지 않는다. 등록·등록 취소는 `roster`(등록 변경 카운터)를 올린다.

## 참가자(entry) 상태

| 상태 | 뜻 |
|---|---|
| `registered` | 등록됨(시작 전) |
| `unregistered` | 본인이 등록 취소. 다시 등록하면 `registered` |
| `dropped` | 시작할 때 참가 자격을 잃어 제외됨(정지·탈퇴·등록 조건 미달) |
| `playing` | 진행 중인 대회의 좌석에 있음 |
| `eliminated` | 탈락(`place` 순위) |
| `won` | 우승(`place` 1) |
| `stopped` | 운영 중단 때 아직 남아 있던 참가자(순위 없음) |

취소된 대회의 참가자는 `registered`로 남는다. "이미 다른 대회에 참가 중" 판단은 참가자 상태와 대회 상태(`registering`·`closed`·`running`)를 함께 본다.

## 등록

- 조건(서버가 매번 확인): 로그인한 활성 회원, 봇 아님, 템플릿의 등록 조건(이메일 인증 필요 여부, 최소 플레이 핸드 수), 대회가 `registering`, 정원 미만, 진행 전이거나 진행 중인 다른 대회에 참가하고 있지 않음.
- 등록은 조건을 모두 WHERE에 넣은 한 문장(INSERT … ON CONFLICT DO UPDATE)이라, 동시에 여러 명이 마지막 자리를 눌러도 정원을 넘지 않는다. 같은 회원이 다시 눌러도 한 행이다.
- 등록 취소는 `registering`·`closed`에서만 된다. 시작 뒤에는 대회를 떠날 수 없다(접속을 끊으면 아래 "접속 끊김"대로 블라인드를 내며 남는다).
- 정원이 차면, 템플릿이 자동 시작이면 등록 요청이 그대로 시작을 부른다. 시작 조건(아래)이 맞지 않으면 등록 상태로 남는다.

## 시작

시작(관리자 또는 자동)은 같은 함수 하나다.

1. 등록자 전원의 자격을 D1에서 다시 읽는다(활성·봇 아님·인증·최소 핸드). 자격을 잃은 등록자는 `dropped`.
2. 자격 있는 인원이 최소 인원(템플릿 `min_players`, 2–정원) 미만이면 시작하지 않는다(409 `tournament_not_ready`). 자동 시작은 정원 전원이 자격이 있을 때만 시작하고, 아니면 자격 잃은 등록만 정리하고 등록을 계속 받는다.
3. 한 D1 batch: 대회 `registering|closed → running`(보던 `version`·`roster`와 같을 때만), 테이블 행 생성(`room_type='tournament'`, 6석, 레벨 1 블라인드), 참가자 `registered → playing`(무작위 좌석, 시작 스택). 첫 문장이 0행이면 상태가 바뀐 것(중복 시작 → 409 `tournament_started`) 또는 등록이 바뀐 것(다시 읽어 최대 3번 재시도)이다.
4. 룸에 `reload`를 보내고, 참가자에게 "대회가 시작되었습니다" 쪽지를 보낸다(대회·회원별 고정 id라 다시 보내도 한 통, 받는 사람의 언어).

룸이 응답하지 않아도 대회는 `running`이다. 룸은 처음 깨어날 때(누가 테이블에 접속하거나 관리자 복구) D1의 참가자 목록으로 좌석을 만든다. 좌석 만들기는 룸에 대회 상태가 없을 때 한 번만 일어난다.

## 블라인드 레벨과 시계

- 레벨은 템플릿의 `[{sb, bb}]` 목록과 레벨 길이(분)로 정한다. 마지막 레벨에 이르면 그대로 유지한다.
- 레벨은 **핸드를 나눌 때** 정해진다. 룸은 새 핸드를 나누기 직전에 시계를 보고 레벨을 올리고, 그 핸드의 블라인드를 엔진에 넘긴다. 진행 중인 핸드의 블라인드는 레벨 시각이 지나도 바뀌지 않는다(다음 핸드부터).
- **레벨 시계는 테이블이 핸드를 나눌 수 있는 동안에만 흐른다.** 일시정지 요청이나 서비스 점검으로 룸이 다음 핸드를 나누지 않는 순간 남은 시간(`level_left_ms`)을 적고 멈추며(`paused_at`), 다시 나누기 시작하는 순간 `지금 + 남은 시간`으로 다음 레벨 시각을 다시 정한다.
- 화면의 "다음 레벨"은 진행 중이면 시각, 멈춰 있으면 남은 시간이다.

## 일시정지·재개

- 관리자 일시정지는 **다음 핸드부터**다: 진행 중인 핸드는 끝까지 진행되고, 그다음 핸드를 나누지 않는다. 그 순간 레벨 시계가 멈춘다.
- 일시정지 중에는 차례가 없으므로 턴 타이머가 없고, 시간 은행은 쓰이지도 보충되지도 않는다(보충은 받은 핸드 수로 센다). 남은 은행·스택·좌석·자리비움 상태는 그대로다.
- 재개하면 룸이 약 2.5초 뒤 다음 핸드를 나누고, 그 순간 레벨 시계가 남은 시간부터 다시 흐른다.
- 서비스 점검도 같은 방식으로 시계를 멈춘다(핸드를 나누지 못하는 동안).
- 일시정지 상태와 시계는 룸 저장소(Durable Object)와 D1에 함께 있어, 룸이 다시 시작해도 같은 규칙이 적용된다.

## 서버 재시작·장애

- 룸(Durable Object)이 다시 시작하면(배포·이동) 저장된 좌석·스택·레벨·다음 레벨 시각·순위·시간 은행·진행 중인 핸드를 그대로 읽는다. 진행 중인 핸드는 같은 마감으로 이어지고, 재시작 중에 지난 차례는 깨어난 알람이 정한다.
- 레벨 시계는 시각(벽시계)으로 저장되므로 짧은 재시작에 멈추지 않는다. 룸이 오래 깨어나지 못했다면 깨어난 뒤 첫 핸드에서 그동안 지난 레벨까지 한 번에 오른다. 이런 대회는 "복구 필요"로 표시된다(아래).
- D1 쓰기(핸드마다의 진행 기록)가 실패하면 룸은 상태를 지키며 15초마다 다시 쓴다. 기록은 매번 전체 상태(순위·스택·레벨)를 보내고 조건부라, 여러 번 써도 결과는 같다. 대회가 끝났을 때 테이블은 D1에 결과가 들어간 뒤에야 닫힌다.
- 룸 저장소를 잃은 경우(정상 운영에서는 없음) 룸은 D1의 마지막 스택 기록으로 좌석을 다시 만든다.

## 접속 끊김

- 접속이 끊긴 참가자도 좌석을 지키며 계속 핸드를 받는다. 차례는 턴 시간 뒤 체크(가능하면) 또는 폴드된다.
- 연속 2번 시간이 지나면 자리비움이 된다. 자리비움인 참가자는 블라인드를 내고 차례가 오면 바로 체크 또는 폴드된다(다른 사람을 기다리게 하지 않음). 다시 접속해 "돌아가기"를 누르면 정상으로 돌아온다. 본인이 자리비움을 고를 수도 있다.
- 대회 좌석은 자리비움이 길어도 일어서지 않는다(캐시 테이블의 10분 규칙 없음). 칩을 모두 잃어야 탈락한다.
- **남은 참가자가 모두 자리비움**이면 새 핸드를 나누지 않는다. 모두 블라인드를 내고 폴드만 하면 마지막 레벨에서는 칩이 서로 오가기만 해 대회가 끝나지 않기 때문이다. 나누지 않는 동안 레벨 시계는 일시정지처럼 멈추고, 누구든 "돌아가기"를 누르면 약 2.5초 뒤 다시 나눈다. 이 상태가 15분을 넘으면 "복구 필요"(`stalled`)로 표시되어 운영자가 운영 중단을 판단한다.
- 관리자의 강제 연결 종료와 회원 정지는 연결만 닫는다. 좌석은 남아 블라인드를 낸다.

## 탈락·순위·종료

- 핸드가 끝났을 때 스택이 0인 참가자는 탈락이다. 순위는 그 핸드 전에 남아 있던 인원 수부터 매긴다(6명 중 첫 탈락은 6위).
- **같은 핸드에서 여러 명이 탈락**하면 그 핸드를 시작할 때 스택이 컸던 사람이 더 높은 순위다. 시작 스택이 같으면 같은 순위(둘 중 높은 쪽)를 함께 받는다.
- 탈락한 참가자의 좌석은 칩 이동 없이 비워지고, 연결은 관전자로 남아 결과를 본다.
- **헤즈업**(2명): 엔진의 2인 규칙(버튼이 스몰 블라인드를 내고 프리플롭에 먼저 행동, 이후에는 나중에 행동)을 그대로 쓴다. 버튼은 다음 살아 있는 좌석으로 옮긴다(이번 버전은 데드 버튼 규칙 없음).
- 블라인드보다 적게 남은 참가자는 남은 칩으로 올인한다.
- 한 명이 남으면 그 참가자가 1위(`won`), 대회는 `finished`(`end_reason='completed'`). 테이블은 결과를 60초 보여 준 뒤 닫힌다. 결과는 대회 화면에서 계속 볼 수 있다.

## 운영 중단(진행 중)과 취소(시작 전)

| | 취소 `cancelled` | 운영 중단 `aborted` |
|---|---|---|
| 언제 | `registering`·`closed` | `running` |
| 확인 | 비밀번호 재확인·사유 | 비밀번호 재확인·사유·대회 이름 입력 확인 |
| 테이블 | 없음 | 진행 중인 핸드는 끝나고, 새 핸드 없이 좌석을 칩 이동 없이 비우고 닫는다 |
| 결과 | 결과 없음 | 이미 탈락한 순위는 남고, 남아 있던 참가자는 `stopped`(순위 없음). 우승자 없음 |
| 안내 | 등록자에게 쪽지 | 참가자(남은 사람과 탈락자)에게 쪽지 |

- 운영 중단 뒤 룸이 끝낸 마지막 핸드의 탈락은 기록되지 않는다(기록은 대회가 `running`일 때만 반영).
- 쪽지는 대회·회원·종류별 고정 id(`INSERT OR IGNORE`)라 조치를 다시 보내도 한 통이다.

## 시작 뒤 관리자가 할 수 없는 일

스택·카드·승자·순위를 바꾸는 경로는 없다. 대회 테이블에는 일반 테이블의 관리자 조치(종료·긴급 제어·설정 변경)를 쓸 수 없고(409 `tournament_table`), 대회 쪽의 일시정지·재개·운영 중단·복구만 쓴다. 턴 타이머 복구는 룸 규칙대로만 움직여 그대로 쓸 수 있다.

## 복구 필요 표시

목록의 "복구 필요" 필터와 상세 화면에 이유 코드로 표시한다. 표시만 하며 자동으로 무엇을 바꾸지 않는다.

| 코드 | 조건 |
|---|---|
| `room_silent` | 진행 중(멈춤 아님)인데 룸의 마지막 기록이 15분보다 오래됨(시작 후 2분 동안 기록이 없을 때 포함) |
| `pause_stuck` | 일시정지를 요청한 지 10분이 지났는데 시계가 멈추지 않음 |
| `resume_stuck` | 재개한 지 2분이 지났는데 시계가 여전히 멈춰 있음 |
| `stalled` | 일시정지 요청이 없는데 시계가 15분 넘게 멈춰 있음(남은 참가자 모두 자리비움, 긴 서비스 점검) |
| `table_open` | 끝났거나 중단된 지 10분이 지났는데 테이블이 닫히지 않음 |
| `start_stuck` | 자동 시작 대회의 정원이 찼는데 2분이 지나도록 `registering`(자동 시작이 자격 문제로 멈췄거나 시작 요청이 실패함) |

`start_stuck`은 룸이 아니라 시작의 문제라 "복구"가 아닌 "시작"(자격 재확인 포함)이나 취소로 처리한다. 관리자의 "복구"는 룸에 다시 읽기(`reload`)를 보낼 뿐이다. 룸은 자기 저장 상태와 D1의 대회 상태로 할 일을 정한다(좌석 만들기, 일시정지 반영, 종료). 결과·스택을 정하지 않는다.

## 권한

| 기능 | 권한 |
|---|---|
| 대회 목록·상세·템플릿 조회 | 기능 `tournaments`(일반 관리자 위임 가능) |
| 템플릿으로 대회 만들기(요약 확인), 등록 마감·해제, 시작, 일시정지·재개, 복구 | 기능 `tournaments` |
| 시작 전 취소, 운영 중단 | 기능 `tournaments` + 비밀번호 재확인 + 사유 |
| 템플릿 만들기·수정·보관(대회 구조: 정원·스택·블라인드·턴 시간·시간 은행·등록 조건) | 능력 `tournament.structure`(최고 관리자) + 재확인 + 사유 + 미리보기 |

모든 조치는 감사 로그(`tournament.*`, 대상 `tournament`/`tournament_template`)에 행위자·대상·사유·변경 전후·결과(성공·거절)를 남긴다. 대회 이력 화면은 이 감사 로그를 대회 id로 읽는다.

## 시간 은행

대회의 시간 은행은 템플릿 값(켜짐, 처음 지급, 최대, 한 번 사용, 보충 핸드 수, 보충량)을 대회를 만들 때 복사해 대회가 끝날 때까지 쓴다. 전체 시간 은행 정책(`time_bank_policies`)의 변경은 대회에 닿지 않는다. 회원별 은행은 한 대회(한 테이블) 동안 이어진다. 일시정지 중의 동작은 위 "일시정지·재개"와 같다.

## API

회원(`apps/api/src/routes/tournaments.ts`, 로그인 필요):

| 메서드·경로 | 내용 |
|---|---|
| `GET /api/tournaments?status=ended&limit=&offset=` | 대회 목록(서버 페이지네이션, 기본은 열린·진행 중, `ended`면 끝난 대회). 내 등록 상태 포함 |
| `GET /api/tournaments/:id` | 대회 상세: 구조·참가자·순위·내 자격(`eligibility`) |
| `POST /api/tournaments/:id/register` | 등록. 자격(정지·봇·인증·최소 핸드·다른 대회 참가 중)과 정원을 서버에서 확인. 정원을 채운 등록이 자동 시작이면 `started: true, tableId` |
| `POST /api/tournaments/:id/unregister` | 시작 전 등록 취소 |

관리자(`apps/api/src/routes/admin-tournaments.ts`, 권한은 위 "권한"):

| 메서드·경로 | 내용 |
|---|---|
| `GET /api/admin/tournaments?status=&q=&recovery=1&limit=&offset=` | 목록(페이지네이션·상태 필터·이름 검색·복구 필요만), 상태별 개수 |
| `POST /api/admin/tournaments` | 템플릿으로 대회 만들기(`preview: true`면 요약만) |
| `GET /api/admin/tournaments/:id` | 상세: 구조·참가자·순위·시계·룸 상태·복구 사유·관리 이력 |
| `POST /api/admin/tournaments/:id/registration` | 등록 마감·다시 열기(`baseVersion`) |
| `POST /api/admin/tournaments/:id/start` | 시작(`baseVersion`, 사유 선택). 자격·인원을 다시 읽고 한 번만 |
| `POST /api/admin/tournaments/:id/cancel` | 시작 전 취소(재확인·사유) |
| `POST /api/admin/tournaments/:id/pause`, `/resume` | 다음 핸드부터 일시정지·재개 |
| `POST /api/admin/tournaments/:id/abort` | 진행 중 운영 중단(재확인·사유·대회 이름 입력) |
| `POST /api/admin/tournaments/:id/recover` | 룸에 대회를 다시 읽게 요청 |
| `GET/POST /api/admin/tournament-templates`, `PUT /:id`, `POST /:id/status` | 템플릿 목록·만들기·수정(버전)·보관(최고 관리자, `preview: true`) |

상태를 바꾸는 요청은 모두 화면이 본 `baseVersion`을 담고, 그 사이 바뀌었으면 409 `tournament_conflict`(템플릿은 `tournament_template_conflict`)로 거절한다. 오류 코드: `tournament_not_found`, `tournament_state`, `tournament_started`, `tournament_not_ready`, `tournament_limit`, `tournament_name_mismatch`, `tournament_structure_invalid`, `tournament_table`, `tournament_template_not_found`, `tournament_template_archived`, `tournament_template_no_change`, `tournament_template_state`.

## 테이블 상태(WebSocket)

대회 테이블의 `state`는 `roomType: 'tournament'`이고 최상위 `tournament`(`packages/types/src/tournament.ts` `TournamentTableView`)에 대회 id·이름·상태, 레벨과 블라인드, 다음 레벨, 시계(`levelEndsAt` 또는 멈춘 동안 `levelLeftMs`), 일시정지, 생존·참가 인원, 시작 스택, 정해진 순위, 보는 사람의 처지(`you`: 진행 중·탈락·우승·중단·관전)를 담는다. 좌석 스택은 대회 칩이다. 착석·일어서기·충전·리바이·대기열 명령은 `tournament_table`로 거절된다. 카드 공개 규칙은 일반 테이블과 같다.

## 배포 순서

마이그레이션 `0026_tournaments` → game-worker → api(web 포함) → admin. 0026은 새 테이블 세 개(`tournament_templates`, `tournaments`, `tournament_entries`)와 인덱스를 만들고 기본 템플릿 하나(6인, 1,500칩, 5분 레벨 13단계, 턴 20초, 시간 은행은 0025 정책 1판과 같은 값, 정원이 차면 자동 시작)를 넣는다. 기존 테이블은 바뀌지 않는다(`tables.room_type`에 SQL 제약이 없어 `tournament`가 그대로 들어간다). 이 템플릿 값은 개발 기본값이며 운영 값은 정하지 않았다. 배포만으로는 대회가 열리지 않는다: 운영자가 대회를 만들어야 한다. 이전 game-worker는 대회 좌석·레벨을 모르므로 **game-worker가 새 버전이 되기 전에는 대회를 만들거나 시작하지 않는다**(이 혼합 상태의 동작은 확인하지 않았다). 되돌릴 때는 진행 중인 대회를 먼저 운영 중단한 뒤 내린다. 이전 api·admin은 새 테이블을 읽지 않으며, 테이블은 남겨 둔다.
