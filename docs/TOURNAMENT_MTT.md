# 멀티 테이블 토너먼트(MTT) 설계 — 구현하지 않음

> 상태: **설계만 있다.** 코드·마이그레이션·화면·플래그 어느 것도 들어가지 않았다(`feat/platform-reliability`, 2026-11-02). 지금 서비스의 토너먼트는 한 테이블 SNG(최대 9명, `docs/TOURNAMENT.md`)뿐이다. 이 문서는 MTT를 만들 때 먼저 정해야 할 구조와 시험 기준을 적어 둔 것이다.

## 왜 SNG를 늘리는 것으로는 안 되나

SNG는 대회 하나 = 테이블 룸(Durable Object) 하나다. 룸이 좌석·스택·레벨 시계·순위를 모두 갖고, D1의 대회 행은 룸이 쓰는 기록이다. MTT는 한 대회가 여러 룸에 걸치므로 다음을 한 곳에서 정해야 한다.

- 테이블 사이 플레이어 이동(밸런싱)과 테이블 합치기(브레이크)
- 대회 전체의 순위(동시에 다른 테이블에서 탈락한 플레이어의 순서)
- 같은 회원이 두 테이블에 앉는 일(중복 참가) 방지
- 레벨 시계와 일시정지가 모든 테이블에 같게 적용되는 것
- 어느 룸이나 조정자가 재시작해도 위 상태가 이어지는 것

## 구조: Tournament Coordinator

- 새 Durable Object `TournamentCoordinator`, 대회 하나에 하나(`idFromName(tournamentId)`). 대회의 진실은 조정자의 저장소와 D1이고, 테이블 룸은 조정자가 배정한 좌석만 플레이한다.
- 조정자가 갖는 것: 참가자별 위치(테이블·좌석·스택·상태), 테이블 목록, 레벨 시계, 순위, 이동 대기열, 처리한 요청 ID(멱등).
- 룸 → 조정자: 핸드가 끝날 때마다 `handDone {tableId, handSeq, stacks, busted[]}`(핸드 번호로 멱등). 탈락 순위는 조정자가 같은 레벨·같은 시각대의 탈락을 시작 스택 순으로 정한다(SNG와 같은 규칙을 대회 전체로).
- 조정자 → 룸: `seat {userId, seatIndex, stack}`, `unseat {userId, moveId}`, `blinds {level}`, `pause`/`resume`, `close`. 룸은 핸드 사이에만 좌석을 바꾼다(진행 중인 핸드의 좌석은 절대 옮기지 않는다).
- 이동은 2단계: 조정자가 `moveId`를 저장 → 원래 룸에서 `unseat`(핸드가 끝난 뒤) → 새 룸에 `seat`. 어느 단계에서 멈춰도 조정자가 깨어날 때 `moveId`로 이어 간다. 스택은 조정자의 기록이 기준이고, 두 룸에 동시에 앉는 순간은 없다(`unseat` 확인 뒤에만 `seat`).

## 밸런싱·브레이크 규칙(초안)

- 테이블 인원 차이가 2 이상이면, 가장 많은 테이블에서 다음 빅 블라인드가 될 플레이어를 가장 적은 테이블의 빈자리로 옮긴다(블라인드 위치를 피해 불공정한 블라인드 회피를 막는다).
- 남은 인원이 (테이블 수 − 1) × 좌석 수 이하가 되면 가장 적은 테이블을 깨고 나머지 테이블에 무작위로 나눈다.
- 파이널 테이블(남은 인원 ≤ 좌석 수)은 한 테이블로 모으고 좌석을 다시 뽑는다.

## 중복 참가·자격

- 등록은 지금처럼 D1 한 문장(조건부 INSERT)이고, 회원은 진행 중이거나 진행 전인 대회 하나에만 참가한다(`ACTIVE_TOURNAMENT_STATUSES`와 같은 규칙).
- 테이블 룸은 좌석을 받을 때 조정자가 준 `moveId`/배정만 받는다. 회원이 직접 MTT 테이블에 앉는 명령은 거절한다(`tournament_table`, SNG와 같음).

## 재시작 복구

- 조정자 재시작: 저장소에서 위치·이동 대기열·시계를 읽고, 진행 중이던 이동을 이어 간다. 저장소를 잃으면 D1의 참가자 행(테이블·좌석·스택·마지막 핸드 번호)으로 다시 만든다.
- 룸 재시작: 지금처럼 진행 중인 핸드를 이벤트 로그로 이어 가고, 끝난 핸드의 `handDone`은 조정자가 받았다고 답할 때까지 다시 보낸다(핸드 번호로 중복 무시).
- 조정자가 응답하지 않으면 룸은 다음 핸드를 시작하지 않는다(잘못된 블라인드나 이미 옮겨진 플레이어로 핸드를 시작하지 않기 위해). 이 상태를 잡는 운영 경고 코드를 지속 운영 경고(`docs/CONTROL_CENTER.md`)에 더한다.

## 플래그와 출시 조건

- 플래그 `MTT_ENABLED`(환경 변수, 기본 꺼짐). 꺼져 있으면 관리자 화면에 MTT 템플릿이 보이지 않고, API가 `multi_table` 구조를 거절한다.
- 켜기 전에 통과해야 할 시험:
  - 단위: 밸런싱·브레이크·동시 탈락 순위, 이동 상태 기계(각 단계에서 중단 후 재개).
  - 통합(wrangler dev): 3테이블 18명 봇 없는 대회를 끝까지, 중간에 조정자 강제 종료·룸 강제 종료 각 1회, 칩 총합 보존·중복 좌석 0·순위 연속성.
  - 부하: 100명 대회의 핸드 종료 → 조정자 처리 지연.
  - 장애 주입은 테스트 환경에서만(`docs/TEST_REPORT.md`의 규칙과 같음).
- 운영 데이터베이스에서 시험하지 않는다. 플래그를 켜는 것은 운영 변경이므로 승인을 받는다.
