# JC ROYAL — 텍사스 홀덤 통합 플랫폼 개발 지시서

> 이 문서는 이전 계획서(docs/PLAN.md v0.11)를 폐기하고 대체하는 유일한 개발 기준이다.
> 브랜드 로고는 `assets/branding/logo.png`(골드 스페이드 + 왕관 + JC 모노그램)를 사용한다. 원본 저장소들의 로고·브랜딩은 모두 이 로고로 교체한다.

## 0. 역할과 최종 목표

당신은 시니어 풀스택 엔지니어이자 실시간 멀티플레이 게임 서버 아키텍트, UI/UX 디자이너다.

프로젝트명은 **JC ROYAL**이다.

아래 GitHub 오픈소스 프로젝트 3개를 분석하고, 각 프로젝트에서 가장 우수한 구현을 선별해 하나의 완성도 높은 **실시간 텍사스 홀덤 웹 플랫폼**으로 통합하라.

단순한 소스코드 복사, 화면 연결 또는 기능 데모가 아니다. 실제 다수의 사용자가 회원가입하고, 로비에서 테이블을 선택하고, 동시에 홀덤을 플레이하고, 가상 칩 잔액과 게임 기록을 관리할 수 있는 서비스를 완성하는 것이 목표다.

서비스는 실제 현금이 아닌 가상 칩을 사용하는 소셜 게임이다. 입금, 출금, 현금 환전, 현금성 보상, 양도 가능한 자산 및 실제 금전 베팅은 구현하지 않는다.

작업은 분석이나 설계서 작성만으로 종료하지 말고 실제 코드 생성, 통합, 실행, 테스트 및 배포 설정까지 진행하라.

https://github.com/Ge-limin/poker-engine-ts

주요 사용 대상:

* No-Limit Texas Hold'em
* 게임 상태 머신

서버에서 이 엔진을 유일한 규칙 판단 주체로 사용하라.

## 3. 권장 통합 기술 스택

가능하면 다음 구조를 채택한다.

| 영역             | 기술                           |
| -------------- | ---------------------------- |
| Frontend       | React, TypeScript, Vite      |
| UI Styling     | Tailwind CSS, shadcn/ui      |
| Animation      | 기존 CSS Animation, 필요시 Motion |
| Audio          | Web Audio API                |
| Backend API    | Hono, TypeScript             |
| Game Engine    | poker-engine-ts              |
| Realtime       | WebSocket                    |
| Game Room      | Cloudflare Durable Objects   |
| Database       | Cloudflare D1                |
| ORM            | Drizzle ORM                  |
| Authentication | 보안 쿠키 기반 세션 인증               |
| Hosting        | Cloudflare                   |
| Monorepo       | pnpm workspaces              |
| Testing        | Vitest, Playwright           |

게임 룸마다 고유한 Durable Object를 배정하여 상태 변경을 직렬화하고, 사용자 계정과 영속 데이터를 D1에 보관하는 아키텍처를 우선 검토한다.

Durable Objects는 SQLite 기반 저장소와 WebSocket Hibernation API를 검토한다. 단, 타이머, 상태 복원, 엔진 패키지의 실제 Edge 호환성을 검증한 후 적용한다.

Bun 전용 API, Node.js 전용 소켓 서버 등 Cloudflare Workers와 충돌하는 부분은 적합한 인터페이스로 교체하라.

실행이 불가능한 구성을 억지로 유지하지 말고, 기술적 원인과 해결책을 문서화하라.

## 4. 프로젝트 구조

다음과 같은 모노레포를 기본으로 구성한다.

## 5. JC ROYAL 브랜드 및 디자인

브랜드명: **JC ROYAL**

로고: `assets/branding/logo.png` (블랙 스페이드 위 골드 테두리·왕관·JC 모노그램). 파비콘, 앱 아이콘, 헤더, 로그인/관리자 화면, 카드 뒷면 등 브랜드 노출 지점에 이 로고(및 여기서 파생한 축소본)를 사용한다. 원본 저장소들의 로고와 브랜딩은 남기지 않는다.

방향성은 프리미엄 온라인 포커룸이다.

디자인 콘셉트:

* 블랙 및 차콜 기반의 다크 UI
* 골드 포인트 컬러
* 에메랄드 그린 포커 테이블
* 고급 카지노 칩 및 플레잉카드
* 간결하면서도 존재감 있는 타이포그래피
* PC 환경에서 몰입감 있는 테이블 중심 구성
* 모바일, 태블릿, PC 반응형 지원

Elite-Poker의 장점인 좌석 구성, 카드 렌더링, 칩 애니메이션, 테이블 테마 시스템을 최대한 유지한다.

단, 지나치게 화려하거나 저렴해 보이는 네온 효과를 지양하고 고급스러운 방향으로 통일한다.

기본 제공 테마는 Royal Black & Gold로 하고 Emerald Classic, Royal Crimson, Sapphire Noir 등의 테마를 추가한다.

인터페이스는 한국어를 기본값으로 하고 영어 전환을 지원한다.

UI 전체에서 일관된 디자인 토큰, 간격, 그림자, 버튼 및 모달 시스템을 사용한다.

## 7. 텍사스 홀덤 구현

가장 중요한 기능이다.

게임 규칙은 poker-engine-ts를 통해 처리한다.

### 기본 게임 기능

* 2~10인 테이블
* No-Limit Texas Hold'em
* 52장 표준 덱
* 프리플랍, 플랍, 턴, 리버, 쇼다운
* 딜러 버튼 및 블라인드 순환
* 폴드, 체크, 콜, 벳, 레이즈, 올인
* 최소 레이즈 계산
* 턴 타이머
* 승자 판정
* 팟 분배
* 사이드팟 처리
* 스플릿 팟
* 핸드별 기록
* 자동 다음 핸드 진행

### 예외 상황

다음 경우도 정상 처리해야 한다.

* 서로 다른 칩 스택으로 다수 올인
* 숏 올인 이후 레이즈 재오픈 제한
* 무승부
* 홀수 칩 분배
* 헤즈업 블라인드 및 액션 순서
* 플레이어 중도 이탈
* 클라이언트 연결 끊김
* 재접속 및 게임 복구
* 중복 액션 제출
* 턴 타임아웃
* 서버 재시작
* 다른 브라우저 탭에서 중복 접속
* 마지막 플레이어만 남는 경우
* 진행 중인 핸드에 관전자가 입장하는 경우

모든 게임 액션은 서버가 검증한다.

클라이언트가 임의로 팟 금액, 칩 잔액, 플레이어 순서, 카드 또는 게임 결과를 결정할 수 없도록 한다.

### 게임 엔진 연결

프런트엔드는 직접 게임 상태를 계산하지 않고 서버에서 전달받은 공개 가능한 상태를 렌더링한다.

구조는 다음과 같다.

사용자 액션 → WebSocket → 인증 및 액션 검증 → poker-engine-ts → 상태 변경 기록 → 플레이어별 상태 전송 → UI 애니메이션.

게임 룰의 기준은 반드시 단 하나여야 한다.

기존 Elite-Poker 및 Ai-Poker의 게임 판정 로직과 충돌할 경우 poker-engine-ts를 우선한다.

단, 엔진이 지원하지 않는 기능은 어댑터 레이어에서 구현하고 테스트한다.

## 8. 실시간 통신과 상태 관리

WebSocket을 사용한다.

이벤트 시스템은 타입 안전하게 설계하며, 런타임 스키마 검증도 수행한다.

필수 이벤트:

* 사용자 인증
* 테이블 생성
* 테이블 입장 및 퇴장
* 관전자 입장
* 플레이어 착석
* 핸드 시작
* 카드 배분
* 베팅 액션
* 턴 변경
* 커뮤니티 카드 공개
* 쇼다운
* 팟 분배
* 핸드 종료
* 게임 상태 복구
* 채팅
* 오류 처리

게임 이벤트에는 고유 ID, 순서 또는 버전 정보를 포함한다.

이벤트 순서를 검증하고, 중복 이벤트가 수신되어도 동일한 게임 액션이 두 번 처리되지 않도록 한다.

재접속 시 서버 상태를 기준으로 클라이언트 화면을 복구한다.

각 플레이어에게는 자신의 홀 카드만 전송한다. 다른 플레이어의 비공개 카드, 전체 덱 순서, 난수 시드 및 숨겨진 게임 상태는 공개하지 않는다.

## 9. 칩 및 게임 경제

**모든 칩은 현금 가치가 없는 플레이 전용 가상 자산이다.**

기본 기능:

* 신규 계정 가상 칩 지급
* 테이블 바이인
* 테이블 칩과 계정 잔액 구분
* 테이블 퇴장 시 잔여 칩 반환
* 게임 종료 시 정산
* 모든 잔액 변경 기록
* 관리자용 가상 칩 조정 기능

정수 단위로 계산하여 부동소수점 오차를 방지한다.

테이블 참여 시 동일한 칩을 두 번 사용할 수 없도록 하며, 지급/차감/반환이 중복 처리되지 않도록 설계한다.

게임 내 총 칩 보존 검증과 계정 원장 검증을 구분한다.

로그, 게임 이벤트, DB 잔액 사이에 불일치가 발생할 경우 자동 감지하고 조정 이력을 남기는 절차를 마련한다.

클라이언트가 칩 수량 변경 요청만으로 자신의 잔액을 증가시킬 수 없어야 한다.

## 12. USB 하드웨어 키 기반 관리자 인증

> **변경 (2026-10-14, 프로젝트 오너 결정):** FIDO/WebAuthn 하드웨어 키가 없어 이 절의 보안 키 인증은 **구현하지 않는다**.
> 관리자 인증은 아이디(이메일)/비밀번호로 하며, 다음 통제를 대신 적용한다.
> - 사용자 사이트와 분리된 관리자 세션(SameSite=Strict, 유휴 30분/최대 8시간)과 관리자 출처 검사
> - 계정·IP별 로그인 시도 제한, 실패 기록
> - 민감 작업 전 비밀번호 재확인(5분)
> - 모든 관리자 조치의 감사 로그
> 아래 원문 요구사항은 이력 보존용이다.

관리자 계정은 일반 회원보다 강력한 인증을 요구한다.

WebAuthn/FIDO2 기반 USB 보안 키를 이용해 관리자 로그인에 추가 인증을 적용한다.

요구사항:

* 관리자 아이디/비밀번호 인증
* WebAuthn 하드웨어 보안 키 인증
* 민감한 관리자 작업 시 재인증
* 키 분실 시 복구 절차
* 복수 키 등록
* 관리자 세션 만료
* 관리자 활동 로그

웹브라우저에서 임의의 USB 저장장치 연결 여부를 읽어 보안 인증을 구현하려고 하지 않는다.

USB 저장장치의 단순 시리얼번호, 정적 파일 또는 비밀 문자열만으로 관리자 인증을 대신하지 않는다.

서버가 실제 WebAuthn 인증 응답을 검증하고 해당 관리자에게 등록된 인증기인지 확인한다.

세 레포 Clone, 구조 분석, 라이선스 검사, 호환성 검토, 재사용 계획 수립.

**Phase 2 — Project Foundation**

모노레포, 공통 TypeScript 설정, 데이터베이스, API, 인증, 기본 UI 구성.

**Phase 3 — Poker Engine Integration**

poker-engine-ts 어댑터 구현, 서버 게임 상태와 룸 관리, 룰 테스트.

**Phase 4 — Multiplayer Integration**

WebSocket, Durable Objects, 테이블 입장, 게임 이벤트, 상태 복구.

**Phase 5 — Elite-Poker UI Integration**

로비, 포커 테이블, 좌석, 카드, 칩, 애니메이션, 사운드 연결.

**Phase 6 — Platform Integration**

회원 정보, 마이페이지, 가상 칩, 게임 기록, 통계.

**Phase 7 — Administration**

관리자 대시보드, 테이블 및 회원 관리, 하드웨어 키 인증.

**Phase 8 — Quality Assurance**

통합 테스트, 보안 검사, E2E, 성능 개선.

**Phase 9 — Deployment**

Cloudflare 설정, GitHub Actions, 환경변수 및 배포 문서.

각 단계는 앞선 단계의 실제 구현과 검증 결과를 기반으로 수행한다.
